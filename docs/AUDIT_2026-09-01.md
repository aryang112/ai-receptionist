# Audit — 2026-09-01 (prompt, recent bundle, prod calls, voice platform)

Scope: the 2026-08-24 Holly bundle + greeting grace (`2b42c88..72aae0f`), the
full system prompt (`buildInstructions`), 66 production calls Aug 23–29 pulled
from the `/admin` API (11 real customers, 55 dev tests), and a Sept-2026
survey of OpenAI Realtime vs xAI Grok Voice vs ElevenLabs Agents.
Method: Fable orchestrating three parallel agents (adversarial code review,
call-QA sweep against `.claude/commands/call-review.md`, web research) with
every claim re-verified in code or recordings before it landed here.

## Verdict

The approach is right: speech-to-speech passthrough with in-process tools,
server-precomputed facts (date, hours status, transfer status), and
deterministic gates in the handlers. The prompt does NOT need a rewrite — it
needed a set of surgical fixes where a prompt rule and a handler gate
disagreed (each one a Holly-class promise-then-walk-back waiting to happen).
Those fixes are in this branch. Two things need Aryan, not code (see
**Needs a decision**).

## Prompt / handler contradictions found (and fixed in this branch)

1. **RICHA'S LINE said "POSSIBLE right now — trust this verbatim" during the active vacation** (Sept 1–9, i.e. today). Handler suppresses the dial; prompt invited the promise. Now: `NOT possible right now (Richa is away until September 10 — messages reach her as a text)`.
2. **"next open Thursday at 12 PM"** with no date when the next opening is ≥7 days out — on Sept 1 that meant Sept 10, callers hear Sept 3. Now `Thursday, September 10 at 12 PM` (hours.ts).
3. **"Send Richa an FYI via transfer_to_owner after a closed-hours change"** live-dialed her cell whenever the salon was closed but her 9–21 window was open (Sunday daytime, Monday before noon). Now a deterministic server-side text from the cancel/reschedule handlers when `!isOpenNow()`; prompt says never to call transfer_to_owner for an FYI.
4. GENERAL RULES "Never guess hours — use get_business_hours / prices — call get_prices" contradicted the hot-loaded HOURS/price sections ("no tool call"). Reworded.
5. RUNNING LATE step 1 scripted a cold "What's your phone number?" even for recognized callers. Reworded to the identification section.
6. Weekly HOURS table omitted the vacation range ("what are your Tuesday hours?" → 12–7 on Sept 8). Vacation ranges now appear under `Closed on:`.
7. Transfer-failback + recognized caller: the injected caller-ID note ordered the STANDARD greeting and a fresh name check, contradicting the failback opening. Failback segments now get a same-call note.
8. New rules from the call evidence: "Is Richa available?" is an availability question (never a service name; never read tool errors aloud); clear-yes-only before book/cancel (garble is not consent); confirm identity at most once, never for price/hours; skip today/tomorrow checks when TODAY'S STATUS says closed.

Code fixes in this branch beyond the prompt:
- **Transfer outcome race**: outcome/endReason now stamped before the awaited Twilio redirect (Twilio's `stop` beats the HTTP response), reverted on failure.
- **Post-goodbye stray**: `OpenAIRealtimeSession.beginHangup()` — tool results are still delivered but never spawn a `response.create` once end_call/transfer has started; `endHangup()` on an aborted goodbye.
- **Owner SMS carries the caller's number** ("a caller called — please follow up" was a follow-up Richa couldn't make).
- `scripts/render-prompt.ts` — render the prompt for any timestamp (`npx tsx scripts/render-prompt.ts 2026-09-06T10:00:00 [fb]`).

Tests: 333 → 347, green in local TZ and `TZ=UTC`, `tsc` clean. No `session.update` shape change (prompt text and handler logic only) — the "greeting plays on the first live call" acceptance still applies.

## Voice platform: stay on OpenAI Realtime, upgrade the model

| | OpenAI Realtime | xAI Grok Voice Agent | ElevenLabs Agents |
|---|---|---|---|
| Architecture | native speech-to-speech (what we run) | native S2S, OpenAI-compatible WS | STT → LLM → TTS pipeline + turn-taking model |
| Twilio / µ-law / tools + barge-in | ✅ `audio/pcmu`, function calls, `conversation.item.truncate` | ✅ µ-law, tools; **no `truncate`** (cancel only), no documented noise reduction | ✅ but ElevenLabs hosts the stream; tools become public webhooks |
| Time-to-first-audio | ~1.1–1.2 s (2.1), 0.8 s (2.1-mini) | ~0.7 s (fastest) | ~1.4 s median on real phone calls |
| 2-min call cost | $0.10–0.30 (2.1, matches observed); $0.03–0.10 (mini) | ~$0.16–0.18 flat | ~$0.19–0.24 + LLM |
| 2026 reliability | WS path clean; SIP incidents Mar/May | multi-day outage Apr 21–23, beta 403s | Feb incidents; concurrency by plan |

- **Do now (no vendor change):** OpenAI shipped `gpt-realtime-2` (May 7) and `gpt-realtime-2.1` / `2.1-mini` (Jul 6) at the same price, explicitly targeting interruption handling, noise, and alphanumerics — our exact pain points. It is one env var (`OPENAI_REALTIME_MODEL=gpt-realtime-2.1`). Per lessons.md, validate on a live call first (greeting plays = accepted); add `reasoning.effort` only after validating the field. Then A/B `2.1-mini` for ~3× lower cost.
- **Grok**: ~0.4 s faster and flat-priced, but no `truncate` (our barge-in), an April multi-day outage, and no evidence it beats GPT-Realtime on tool accuracy. Keep as a feature-flagged experiment, not primary.
- **ElevenLabs**: slower on real calls, not cheaper once the LLM is added, and a rewrite (number moves to them, 11 tools become webhooks, watchdog/failback/greeting-grace rebuilt around their events). A Realtime-text + ElevenLabs-TTS hybrid throws away the prosody we pay for. Skip.
