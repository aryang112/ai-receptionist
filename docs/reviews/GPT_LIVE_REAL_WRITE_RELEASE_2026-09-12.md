# Live real appointment writes — direct-number pilot

The owner explicitly authorized real Phorest appointment creation, rescheduling and cancellation, and access for all callers to the direct number while external salon call forwarding remains off. The old Live implementation only simulated these changes. This release connects the existing single-appointment prepare/confirm tools to real writes; grouped visits are a separate design proposal in `docs/GPT_LIVE_GROUPED_VISIT_PLAN_2026-09-12.md`.

## Implementation

- Removed the Live-only simulation startup/proposal restriction. Raw mutation tools remain unavailable to Live; exact proposals and explicit approval remain required. Proposal replacement is blocked during a pending write, duplicate confirms reuse the same result, and an uncertain real outcome prevents subsequent mutations on that call.
- Real mode accepts all direct callers through the existing Twilio signature and stream-token validation. The old two-number list is retained only for simulation rollback; it is not an admission restriction in real mode. Public admission does not authorize a guessed client ID: account reads and explicit-client bookings require a server-observed phone match or caller-ID prefetch. Name-only candidate searches no longer surface strangers' appointment details. This is contact matching under the current identity flow, not an OTP authentication system.
- Real Live bookings/moves stop before writing when fresh availability cannot be verified. Existing ownership checks, canonical IDs, local calendar restrictions and Phorest timezone normalization remain in place.
- Live real provider writes verify persisted state before success: create checks ID/client/service/local time and ACTIVE/BOOKED; update checks target time and ACTIVE/BOOKED; cancellation requires explicit canceled/inactive state. Writes are never retried. Verification alone uses up to three reads with short pauses on an unverified result; create targets the known client/date, and cancellation reads explicitly include canceled records.
- Phorest returns fractional-second strings such as `12:15:00.000`; verification now normalizes that representation. Unknown outcomes invalidate cached appointment lists so subsequent reads do not use pre-write data. Configuration telemetry now reports the actual simulation mode.
- Appointment writes and owner communications are independent. Runtime owner SMS and transfers remain simulated; digest and post-call summary are disabled. No unsolicited call or SMS was initiated. Existing voice, interruption behavior, public hours, transfer-day policy, three-choice availability and external forwarding configuration were not changed.
