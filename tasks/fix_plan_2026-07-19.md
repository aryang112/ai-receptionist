## LANE B — OpenAI session layer (parallel with A; owns openaiSession.ts ONLY)

**B0 — live error-capture protocol (do before B2/B3/B4)**
Write `scripts/probe-realtime-errors.ts` (read-only, uses env key): connect a
GA session, deliberately trigger (a) `response.create` while a response is
active, (b) `conversation.item.truncate` with absurd `audio_end_ms`, (c) a
bogus session field on a THROWAWAY session. Record exact `error.code`/`type`
strings into the script's output + paste into the commit message. These
strings parameterize B2/B3. DO NOT guess them.

**B1 — RT-1 onClose propagation**
Handlers interface: add `onClose?: () => void`. In `ws.on('close')`: if not an
intentional `close()` (track `this.closing`), invoke it. No behavior change
for intentional shutdown. Test: simulated unexpected close fires onClose once;
`close()` fires none.

**B2 — RT-2 response-state tracking**
Track `activeResponse: boolean` via `response.created` / `response.done`.
`sendToolResult`: always send `conversation.item.create` (function output);
if `activeResponse` → set `pendingResponseCreate = true` instead of sending
`response.create`; on `response.done` → if pending, clear flag and send it.
Belt+braces: the B0-captured "already has active response" error code is
swallowed as non-fatal (see B3). Tests: tool result during active response
defers exactly one `response.create` until done.

**B3 — RT-3 error classification + circuit breaker**
In the `error` event case: **default = log-and-continue** (do NOT invoke
`handlers.onError`). Escalate to `onError` ONLY for: WS/connection failures,
auth errors, `session.update` rejections (session-fatal), or when the circuit
breaker trips: ≥3 error events within 10s → escalate once. Use B0-captured
codes for the known-benign list (active-response collision, truncate-range,
rate-limit). Test: single benign error → session alive; 3-in-10s → onError once.

**B4 — RT-5 failed-response detection**
`response.done`: check `event.response.status`. `'failed'`: if failure is
rate-limit (match B0/`rate_limits.updated` state), schedule ONE retry
`response.create` after `reset_seconds` (cap 10s, only if session still open
and no active response); other failures → log error + count toward B3 breaker.
`'cancelled'` = normal (barge-in), ignore. Never call `onResponseComplete`
cleanup differently — keep existing flow.

**B5 — RT-7 stray-delta gating**
On barge-in truncate (or `response.cancelled`), record the cancelled
`response_id`; drop subsequent `audio.delta`s carrying it (no onAudioChunk, no
item re-arm). Clears on next `response.created`. Test: post-cancel deltas for
the old id produce zero onAudioChunk calls.

**B6 — RT-9 call-tagged logging**
Constructor accepts optional `callTag?: string`; create a pino child logger
`logger.child({ call: callTag })` used for ALL session logs (⏱/📊/⚖️/
transcripts). Default undefined = current behavior (so Lane C wiring is a
one-liner later, non-breaking now).
